## 1. Which Veo models exist now, with exact IDs, launch stages, dates and deprecations? Is there a "Veo 3 Lite" or a Veo 4?

### Takeaway
No model is called "Veo 3 Lite". The client's model is almost certainly **Veo 3.1 Lite**, and Google's current official Vertex/Agent Platform notebook calls it **`veo-3.1-lite-generate-001`**. Its public preview launched on Vertex AI around **April 2–3, 2026**. Docs (search summary) still label it "Preview". The current Veo family on Google Cloud is **Veo 3.1** (`veo-3.1-generate-001`), **Veo 3.1 Fast** (`veo-3.1-fast-generate-001`) and **Veo 3.1 Lite** (`veo-3.1-lite-generate-001`). The `-preview` IDs remain for some features. Veo 3.0 and Veo 2.0 endpoints were scheduled for shutdown on June 30, 2026. **No Veo 4 has been announced.** Google's newest video model line is **Gemini Omni Flash / Gemini Omni 1.1 Flash**, a separate family. Vertex AI itself was renamed **Gemini Enterprise Agent Platform** (April 22, 2026).

## 2. What does Veo 3.1 Lite support or NOT support compared with Veo 3.1 / Fast (and Gemini Omni 1.1 Flash)?

### Takeaway
Veo 3.1 Lite supports **text-to-video**, **image-to-video** (start frame), **first+last frame interpolation**, **native audio including dialogue**, **4/6/8 s** clips, **16:9 and 9:16**, **720p and 1080p** (no 4K), **up to 4 samples per request**, `seed`, `negativePrompt`, `personGeneration` and GCS output. It does **NOT support reference images ("Ingredients to video" / asset or style references)**. Ingredients are the main identity-locking tool for keeping the same avatar across shots. **Video extension on Lite is contested**: current Google Cloud docs and Google's sample app say supported (7 s), while the older Gemini API preview page and most third parties say not. Full Veo 3.1 and Fast add 4K and reference-to-video (up to 3 asset images, 8 s only). Gemini Omni 1.1 Flash adds explicit per-character image binding, conversational edits and 10 s multi-turn extension that keeps dialogue.

### Inferences
- For the client's pain point #3 (avatar drifts between clips): Lite has **no reference-image identity lock**. The only identity anchors on Lite are (a) the **same start frame** (i2v), from the existing still-image avatar SOP, (b) **first+last frame** with the same face, and (c) **extension** (if it works on Lite), which continues from the last frames rather than re-imagining the face. If chained clips keep drifting, the documented fixes are: use full Veo 3.1 / Fast with up to 3 asset references (8 s clips only), or use Omni 1.1 Flash with `<IMAGE_REF_n>` binding.
- For pain point #5 (several characters): Veo r2v accepts at most 3 asset images in total, so two characters plus one set at most. Omni's tag binding is the only documented per-character binding mechanism. It is single-source (Gemini API cookbook) and preview.
- `requires_prompt_enhancement=True` in Google's own app, plus the docs calling `enhancePrompt` "Veo 2 only", suggests the **LLM prompt rewriter is effectively always on for Veo 3.x**. It could paraphrase dialogue or drop accent instructions, which matters for pain points #1 and #2. This is an inference and has not been verified. Test by sending `enhancePrompt: false` and comparing.
- Extension output is a 7 s continuation. Mixing Lite-generated base clips with extension on a different model ID (the notebook uses `veo-3.1-generate-preview`) could change voice or look. Keep base and extension on the same model where possible (inference).

### Gaps
- There is no official statement on whether Veo 3.1 Lite can extend **its own** 1080p output, or whether extension output resolution is capped at 720p on Vertex.
- There is no official statement on **supported speech languages and accents** for Veo 3.1 dialogue (searched; nothing found). This leaves pain point #2 without a spec-level answer.
- Whether `seed` stays deterministic when the rewriter is on is not documented.
- No official per-model maximum prompt length was found.

## 4. What does a Vertex AI / Agent Platform request look like (SDK and REST)?

### Takeaway
Veo uses a long-running operation. The SDK path is `client.models.generate_videos(...)` then poll `client.operations.get(op)`. The REST path is `POST …/publishers/google/models/{MODEL_ID}:predictLongRunning` with `instances[]` (prompt, image, lastFrame, video, referenceImages, mask) and `parameters{}` (aspectRatio, durationSeconds, resolution, sampleCount, seed, negativePrompt, personGeneration, generateAudio, enhancePrompt, storageUri, compressionQuality, resizeMode, fps, pubsubTopic). Poll with `:fetchPredictOperation`.

### Cited Findings
- **Official SDK example, Veo 3.1 Lite on Agent Platform** (copied verbatim from the Google notebook, 2026-10-26):
  ```python
  from google import genai
  from google.genai import types
  client = genai.Client(enterprise=True, project=PROJECT_ID, location="us-central1")
  operation = client.models.generate_videos(
      model="veo-3.1-lite-generate-001",
      prompt=prompt,
      config=types.GenerateVideosConfig(
          aspect_ratio="16:9",
          number_of_videos=1,
          duration_seconds=8,
          resolution="720p",
          person_generation="allow_adult",
          generate_audio=True,
      ),
  )
  while not operation.done:
      time.sleep(10)
      operation = client.operations.get(operation)
  ```
  — [GCP notebook veo3_video_generation](https://github.com/GoogleCloudPlatform/generative-ai/blob/main/vision/getting-started/veo3_video_generation.ipynb). The original code has the model string in a variable. Image-to-video adds `image=types.Image.from_file(location=starting_image)`. GCS output adds `output_gcs_uri="gs://…"` and returns `generated_videos[0].video.uri`. Without it the call returns `video.video_bytes`. — same source
- **Official first+last frame example** (verbatim structure): `image=types.Image(gcs_uri=first_frame_gcs, mime_type="image/png")` plus `config=types.GenerateVideosConfig(last_frame=types.Image(gcs_uri=last_frame_gcs, mime_type="image/png"), output_gcs_uri=output_gcs, aspect_ratio="16:9", number_of_videos=1, duration_seconds=6, resolution="1080p", person_generation="allow_adult", generate_audio=True)`. — [veo3_advanced_controls](https://github.com/GoogleCloudPlatform/generative-ai/blob/main/vision/getting-started/veo3_advanced_controls.ipynb)
- **Official reference-to-video example:** `reference_images=[types.VideoGenerationReferenceImage(image=types.Image.from_file(location=first_image), reference_type="asset"), …]`, used with `veo-3.1-fast-generate-preview` and `duration_seconds=8`. — [veo3_reference_to_video](https://github.com/GoogleCloudPlatform/generative-ai/blob/main/vision/getting-started/veo3_reference_to_video.ipynb)
- **Official extension example:** `model="veo-3.1-generate-preview", video=types.Video(uri=video_gcs, mime_type="video/mp4"), config=types.GenerateVideosConfig(output_gcs_uri=output_gcs, number_of_videos=1, duration_seconds=7, person_generation="allow_adult", generate_audio=True)`. — [veo3_advanced_controls](https://github.com/GoogleCloudPlatform/generative-ai/blob/main/vision/getting-started/veo3_advanced_controls.ipynb)
- **REST field names** (SDK → Vertex wire mapping in `_GenerateVideosConfig_to_vertex`):
  - In `instances[0]`: `lastFrame`, `mask`, `referenceImages`.
  - In `parameters`: `aspectRatio`, `compressionQuality`, `durationSeconds`, `enhancePrompt`, `fps`, `generateAudio`, `negativePrompt`, `personGeneration`, `pubsubTopic`, `resizeMode`, `resolution`, `sampleCount`, `seed`, `storageUri`.
  — [python-genai models.py](https://github.com/googleapis/python-genai/blob/main/google/genai/models.py)
- **Google sample-app REST body** (verbatim from `compose_videogen_request`; endpoint `https://us-central1-aiplatform.googleapis.com/v1/projects/{PROJECT}/locations/us-central1/publishers/google/models/{MODEL}:predictLongRunning`, polled via `{MODEL}:fetchPredictOperation` with `{"operationName": lro_name}`):
  ```json
  {"instances": [{"prompt": "...", "image": {"gcsUri": "gs://...", "mimeType": "png"}, "lastFrame": {"gcsUri": "gs://...", "mimeType": "png"}}],
   "parameters": {"storageUri": "gs://...", "sampleCount": 1, "seed": 1234, "aspectRatio": "9:16", "durationSeconds": 8, "enhancePrompt": "yes"}}
  ```
  — [models/veo.py](https://github.com/GoogleCloudPlatform/vertex-ai-creative-studio/blob/main/models/veo.py). Note that this legacy helper sends `"mimeType": "png"` and `enhancePrompt` as a string. The SDK path uses `image/png` and a boolean.
- **Gemini API REST** (AI Studio key, not Vertex): `POST https://generativelanguage.googleapis.com/v1beta/models/${VEO_MODEL_ID}:predictLongRunning?key=…` with `{"instances":[{"prompt":"…"}],"parameters":{"aspectRatio":"16:9","resolution":"1080p","negativePrompt":"cars","sampleCount":1}}`. The result is at `.response.generateVideoResponse.generatedSamples[].video.uri`. — [cookbook Get_started_Veo_REST](https://github.com/google-gemini/cookbook/blob/main/quickstarts/Get_started_Veo_REST.ipynb)
- The Gemini API supports webhooks on the `video.generated` event instead of polling. — [cookbook Get_started_Veo](https://github.com/google-gemini/cookbook/blob/main/quickstarts/Get_started_Veo.ipynb). On Vertex the equivalent field is `pubsubTopic` / `pubsub_topic`. — [python-genai types.py](https://github.com/googleapis/python-genai/blob/main/google/genai/types.py)
- **Omni (Interactions API) request shape on Agent Platform** (verbatim structure): `client.interactions.create(model="gemini-omni-1.1-flash-preview", input=[{"type":"text","text":prompt},{"type":"image","mime_type":"image/png","data":b64}], generation_config=interactions.GenerationConfig(video_config=interactions.VideoConfig(task="image_to_video")), response_format=interactions.VideoResponseFormat(aspect_ratio="16:9", duration="6s", resolution="720p"))`. Multi-turn edits and extensions pass `previous_interaction_id=…`. — [GCP notebook Omni 1.1](https://github.com/GoogleCloudPlatform/generative-ai/blob/main/vision/getting-started/gemini_omni_1_1_flash_video_gen.ipynb)
- **Official Google meta-prompt for turning keywords into a Veo prompt** (useful for Jarvis), run with `gemini-3.8-flash` in the official notebook: "You are an expert video prompt engineer for Google's Veo model. Your task is to construct the most effective and optimal prompt string using the following keywords. Every single keyword MUST be included. Synthesize them into a single, cohesive, and cinematic instruction. Do not add any new core concepts. Output ONLY the final prompt string…" Its keyword slots are Subject, Action, Scene, Camera angles, Camera movements, Lens effects, Style, Temporal elements and Audio (sound effects plus dialogue). — [GCP notebook veo3_video_generation](https://github.com/GoogleCloudPlatform/generative-ai/blob/main/vision/getting-started/veo3_video_generation.ipynb)

### Inferences
- For a pipeline driven by Jarvis, the minimal "Lite talking-avatar" call is: `model=veo-3.1-lite-generate-001`, `image=<approved avatar still>` (i2v, so identity comes from the frame), `aspect_ratio="9:16"`, `resolution="1080p"`, `duration_seconds=8`, `generate_audio=True`, `person_generation="allow_adult"`, `number_of_videos=2–4`, a fixed `seed` per shot, and `output_gcs_uri`.
- Use `labels` (billing tracking) per campaign/client.

### Gaps
- I could not read the English Agent Platform model-reference page to confirm the max prompt length, `fps` allowed values, `resizeMode` scope ("Veo 3 image-to-video only" per the search summary), or whether `compressionQuality: LOSSLESS` is available on Lite.
